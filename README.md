# 1. SQL — базовые знания

## 1.1. SELECT и JOIN

Даны две таблицы:

```text
T1 (ID int, Text1 ..., Text2 ... и т.д.)
T2 (ID int, Text1 ..., Text2 ... и т.д.)
```

### 1. Вывести все поля из обеих таблиц для записей, у которых ID совпадают

```sql
SELECT *
FROM T1
INNER JOIN T2
    ON T1.ID = T2.ID;
```

### 2. Вывести все записи из T1 и только имеющиеся записи из T2

```sql
SELECT *
FROM T1
LEFT JOIN T2
    ON T1.ID = T2.ID;
```

### 3. Вывести все записи из T1, для которых таких ID нет в T2

```sql
SELECT T1.*
FROM T1
LEFT JOIN T2
    ON T1.ID = T2.ID
WHERE T2.ID IS NULL;
```

## 1.4. Что такое hints

**Hints** — это директивы SQL Server, позволяющие разработчику влиять на выбор плана выполнения запроса, использование индексов, блокировок и других механизмов оптимизации.

Использовать hints нужно осторожно, поскольку неверная подсказка оптимизатору может ухудшить производительность запроса.

---

## 1.5. Виды блокировок

Основные блокировки SQL Server:

- **Shared (S)** — используется при чтении;
- **Exclusive (X)** — используется при изменении данных;
- **Update (U)** — используется при подготовке к изменению.

Также существуют:

- intent-блокировки;
- блокировки схемы;
- блокировки диапазонов ключей.

Блокироваться могут строки, страницы или целые таблицы.

---

## 1.6. Что такое транзакция

**Транзакция** — это группа операций с БД, которая рассматривается как единая операция: либо все изменения успешно фиксируются, либо при ошибке откатываются.

Основные свойства транзакций описываются принципами **ACID**:

- **Atomicity** — либо выполняются все операции, либо ни одна;
- **Consistency** — данные переходят из одного корректного состояния в другое;
- **Isolation** — параллельные транзакции не должны некорректно влиять друг на друга;
- **Durability** — после `COMMIT` изменения сохраняются даже при сбое.

---

## 1.7. DELETE и TRUNCATE

`DELETE` — построчное удаление данных, поддерживает `WHERE`.

`TRUNCATE` — быстрая очистка всей таблицы без `WHERE`; в SQL Server дополнительно сбрасывает счётчик `IDENTITY`.

## 2.1. Хранимая процедура перевода средств

Есть таблица счетов `T`:

- `N` — номер счёта;
- `S` — сумма на счёте.

Процедура должна:

1. принимать номера двух счетов `@N1`, `@N2`;
2. принимать сумму `@S`;
3. проверить наличие средств;
4. перевести средства в рамках транзакции.

```sql
CREATE PROCEDURE TransferMoney
    @N1 INT,
    @N2 INT,
    @S DECIMAL(18, 2)
AS
BEGIN
    SET NOCOUNT ON;

    BEGIN TRY
        BEGIN TRANSACTION;

        -- Проверяем наличие средств на первом счёте
        IF NOT EXISTS (
            SELECT 1
            FROM T
            WHERE N = @N1
              AND S >= @S
        )
        BEGIN
            ROLLBACK TRANSACTION;
            THROW 50001, N'Недостаточно средств на счёте.', 1;
        END;

        -- Списываем деньги с первого счёта
        UPDATE T
        SET S = S - @S
        WHERE N = @N1;

        -- Зачисляем деньги на второй счёт
        UPDATE T
        SET S = S + @S
        WHERE N = @N2;

        COMMIT TRANSACTION;
    END TRY
    BEGIN CATCH
        IF @@TRANCOUNT > 0
            ROLLBACK TRANSACTION;

        THROW;
    END CATCH;
END;
```

## 2.3. Диагностика проблемы автоматического задания

Автоматическое задание выполняется каждую минуту и выбирает лоты следующим запросом:

```sql
SELECT Bid.Id, Purchase.OrgBuId, Purchase.TypeId
FROM Bid
JOIN Purchase ON Purchase.Id = Bid.PurchaseId
WHERE Bid.StatusId = 6;
```

Проблема возникла потому, что запрос при каждом запуске снова выбирает все записи с `Bid.StatusId = 6`. После формирования документа запись продолжает удовлетворять условию выборки, поэтому документ создаётся повторно каждую минуту.

На тестовом сервере мог отсутствовать набор данных, при котором проблема проявлялась, либо существовал функционал изменения атрибута `StatusId`, который не был перенесён или включён на боевом сервере.

Возможные решения:

### Вариант 1. Изменять статус после успешной обработки

Например:

```text
Bid.StatusId = 6 → Bid.StatusId = 7
```

### Вариант 2. Добавить отдельный признак создания документа

Например, поле:

```text
Bid.IsDocumentCreated
```

и изменить выборку:

```sql
SELECT Bid.Id, Purchase.OrgBuId, Purchase.TypeId
FROM Bid
JOIN Purchase ON Purchase.Id = Bid.PurchaseId
WHERE Bid.StatusId = 6
  AND Bid.IsDocumentCreated = 0;
```

После успешного создания документа `Bid.IsDocumentCreated` должен изменяться.

### Вариант 3. Проверять существование документа

Можно выбирать только те лоты, для которых документ «Результаты торгов» ещё не создан.

# 3. Понимание базовых концепций программирования

## 3.1. Валидность XML

В предложенном XML присутствуют следующие ошибки:

1. Отсутствует единый корневой элемент.
2. В тексте `Конкурс с ценой < 500 000 руб.` символ `<` интерпретируется как начало тега. Его необходимо заменить на:

```xml
&lt;
```

3. Открывающий и закрывающий теги отличаются регистром:

```xml
<PurchaseInfo>
...
</Purchaseinfo>
```

XML регистрозависим, поэтому имена открывающего и закрывающего тегов должны полностью совпадать.

---

## 3.2. Поиск дублей в массиве

Необходимо за один проход определить наличие повторяющихся элементов в большом массиве `int32`.

Для этого используется `HashSet<int>`:

```csharp
static bool HasDuplicates(int[] M)
{
    var seenElements = new HashSet<int>();

    foreach (var number in M)
    {
        if (seenElements.Contains(number))
        {
            return true;
        }

        seenElements.Add(number);
    }

    return false;
}
```

Идея: каждый встреченный элемент сохраняется в `HashSet`. Если очередное значение уже присутствует в множестве, значит найден дубликат.

# 4. Инженерия и обработка информации

## 4.1. Экономика

Есть две системы налогообложения:

1. 6% от доходов;
2. 15% от разницы `доходы - расходы`.

Требуется определить долю расходов от доходов, при которой сумма налога одинакова.

Пусть доход равен `x`, расходы — `y`.

```text
0,06x = 0,15(x - y)
```

Для `x = 1`:

```text
0,06 = 0,15(1 - y)
0,15y = 0,09
y = 0,6
```

**Ответ: 60% от доходов.**

## 4.2. Инженерная задача

Дано:

- длина провода — `184,2 м`;
- высота столбов — `100 м`;
- нижняя точка провода находится на высоте `7,9 м` от земли.

Провод опускается относительно вершины столба на:

```text
100 - 7,9 = 92,1 м
```

Половина длины провода:

```text
184,2 / 2 = 92,1 м
```

То есть каждая половина провода должна идти строго вертикально вниз. Следовательно, горизонтального расстояния между столбами нет.

**Ответ: 0 м.**

В общем виде задача для цепной линии может быть выражена через:

```text
s — длина половины провода
f — высота столба минус высота нижней точки

a = (s² - f²) / (2f)

x = 2a · asinh(s / a)
```

В данном случае `a = 0`, что соответствует предельному вертикальному положению провода.

## 4.3. Поиск и структурирование информации

### 4.3.1. Как устроена система государственных закупок в Российской Федерации?

Система государственных закупок в России — это регулируемый процесс приобретения товаров, работ и услуг для государственных и муниципальных нужд.

Она базируется прежде всего на двух законах:

- **44-ФЗ** — закупки для государственных и муниципальных нужд;
- **223-ФЗ** — закупки отдельными видами юридических лиц, например компаниями с государственным участием.

#### Участники системы

- **Заказчики** — государственные органы, казённые и бюджетные учреждения, госкомпании.
- **Поставщики** — юридические лица, индивидуальные предприниматели или физические лица, предлагающие товары или услуги.
- **Контрольные органы** — ФАС, Казначейство, Счётная палата.
- **Операторы площадок** — электронные платформы для проведения торгов.

#### Основные этапы закупки

1. **Планирование** — заказчик создаёт план-график закупок.
2. **Извещение** — публикуется информация о закупке.
3. **Подача заявок** — участники предлагают цены и условия.
4. **Торги и выбор победителя** — определяется поставщик.
5. **Заключение контракта** — заключается договор между заказчиком и победителем.

#### Основные ресурсы

- **ЕИС** — единая информационная система, где публикуется информация о закупках, планах и отчётах.
- **Электронные площадки** — например, Сбербанк-АСТ и РТС-тендер, на которых проводятся торги.

---

### 4.3.2. Что регулирует 44-ФЗ?

Федеральный закон № 44-ФЗ «О контрактной системе в сфере закупок товаров, работ, услуг для обеспечения государственных и муниципальных нужд» регулирует отношения, направленные на обеспечение государственных и муниципальных нужд.

К основным направлениям регулирования относятся:

- планирование закупок товаров, работ и услуг;
- определение поставщиков, подрядчиков и исполнителей;
- заключение государственных и муниципальных контрактов;
- особенности исполнения контрактов и приёмки результатов;
- аудит результатов закупок и контроль за соблюдением законодательства.

---

### 4.3.3. Что регулирует 223-ФЗ?

Федеральный закон № 223-ФЗ «О закупках товаров, работ, услуг отдельными видами юридических лиц» регулирует общие принципы и порядок закупок компаний с государственным участием, естественных монополий и организаций, осуществляющих регулируемые виды деятельности.

К заказчикам относятся, в частности:

- государственные корпорации и государственные компании;
- субъекты естественных монополий;
- организации, осуществляющие регулируемые виды деятельности в сфере электроснабжения, газоснабжения и водоснабжения;
- хозяйственные общества с долей участия государства или муниципальных образований более 50%;
- дочерние хозяйственные общества указанных организаций;
- бюджетные учреждения при осуществлении определённых закупок за счёт грантов, средств от приносящей доход деятельности и средств субподряда.

Закон обязывает заказчиков разработать и разместить в ЕИС собственное **Положение о закупке**, регулирующее их закупочную деятельность.

---

### 4.3.4. Что такое B2B?

**B2B (Business-to-Business, «бизнес для бизнеса»)** — модель коммерческого взаимодействия, при которой одна компания продаёт товары, работы или услуги другим компаниям для обеспечения их деятельности.

Пример: **регистрация нового сотрудника в IT-системах компании**.

![Бизнес-процесс регистрации нового сотрудника](images/business-process.png)

1. HR оформляет нового сотрудника.
2. HR формирует заявку на регистрацию сотрудника в IT-системе.
3. Системный администратор получает заявку.
4. Параллельно:
   - создаётся корпоративная учётная запись;
   - подготавливается рабочее место;
   - определяются необходимые доступы.
5. После завершения всех действий администратор передаёт сотруднику оборудование и учётные данные.
6. Новый сотрудник выполняет первый вход.
7. Если вход успешен:
   - сотрудник подтверждает доступ;
   - HR получает подтверждение;
   - процесс завершается.
8. Если вход неуспешен:
   - сотрудник сообщает о проблеме;
   - системный администратор устраняет её;
   - сотрудник повторяет вход.

# Запуск опционального задания

## Требования

- Visual Studio;
- .NET SDK для MVC-проекта;
- .NET Framework для Web Forms;
- SQL Server Express;
- SQL Server Management Studio — опционально, для удобной работы с БД.

## База данных

В репозитории находится SQL-скрипт для развёртывания базы данных.

Выполните его в SQL Server:

```text
database/database.sql
```

Скрипт создаёт необходимые объекты базы данных и хранимые процедуры.

## Строка подключения

Для локального SQL Server Express используется подключение к экземпляру:

```text
.\SQLEXPRESS
```

Перед запуском при необходимости измените строку подключения под своё окружение.

## MVC

Проект реализован на ASP.NET Core MVC.

Основные возможности:

- просмотр списка;
- просмотр карточки;
- создание;
- редактирование;
- удаление;
- поиск по XML-оглавлению;
- HTML-редактор оглавления.

## Web Forms

Вторая реализация выполнена на ASP.NET Web Forms.

Реализован тот же набор функций:

- список книг;
- карточка;
- создание;
- редактирование;
- удаление;
- поиск;
- работа с XML;
- HTML-редактор оглавления.
